# База заинтересованных в запуске

Формы на главной и странице «О нас» отправляют данные в Rails через `POST /launch_subscriptions`. Запрос защищён CSRF. До отправки нужны корректная почта и отмеченное согласие. Если сохранение не удалось, попап успеха не показывается, поля остаются для повторной попытки.

Адреса хранятся в PostgreSQL в таблице `launch_subscriptions`:

- `email` — почта в нижнем регистре без пробелов по краям; уникальный индекс предотвращает дубли.
- `consent_accepted_at` — время получения согласия.
- `source` — `map` или `about`, страница первого обращения.
- `created_at`, `updated_at` — время создания и обновления записи.

Повторная подписка возвращает такое же подтверждение, не меняя дату первоначального согласия. Публичного списка адресов нет. Параметр email исключён из журналов Rails существующим фильтром.

## Что показать преподавателю

1. На главной введите свою почту и отметьте согласие.
2. Нажмите «Узнать о запуске» — после сохранения появится попап.
3. Откройте `/admin`, войдите и выберите «Подписчики».
4. Покажите адрес, дату согласия, страницу и общее число уникальных подписчиков.
5. Отправьте ту же почту повторно: число записей не увеличится.
6. При необходимости покажите миграцию `db/migrate/20261025233000_create_launch_subscriptions.rb`, модель и контроллер. Число записей можно проверить через `bin/rails runner 'puts LaunchSubscription.count'`.

Тестовые адреса автоматических проверок создаются в отдельной тестовой базе, не среди настоящих подписчиков. Миграция создаёт новую таблицу и не меняет существующие статьи.

## Ограничения

Это сбор адресов для будущего уведомления, а не готовая рассылка: письма пока не отправляются. Рабочие адреса не включаются в GitHub — там только код. При переносе на сервер нужна миграция и отдельный перенос базы. GitHub Pages не запускает этот обработчик Rails.

# Профиль пользователя

- `/register` — регистрация, `/login` — вход, `/profile` — личный кабинет.
- Пользователи хранятся в `users`, пароли — только bcrypt-хеши. Аккаунт пользователя не даёт прав администратора.
- Почта и ник уникальны, нормализуются в нижний регистр. Пароль: 12–72 символа.
- Настройки требуют текущий пароль. Сохранение настроек отзывает другие пользовательские сессии.
- Статьи сохраняются из статьи или панели карты кнопкой «В избранное» (`saved_places`).
- Маршруты сохраняются кнопкой на карточке каталога (`saved_routes`).
- «Предложить маршрут» и «Пополнить архив» создают `profile_submissions`, начальный статус всегда `pending`. Пользователь не может назначить себе статус или другого владельца.
- `/admin/profile_submissions` — рассмотрение предложений автором: приняты / на модерации / нужно уточнить. Принятие меняет статус в профиле, но не создаёт автоматически статью Place или маршрут в каталоге.
- Фото и карты загружаются как JPG/PNG/WebP/GIF, максимум 10 МБ. Звук пока добавляется ссылкой в описании.
- Предпочтения уведомлений сохраняются, отправка почты и восстановление пароля через почту пока не подключены.
- Пустые новые аккаунты не заполняются чужими демонстрационными материалами.

## Изображения

Временная общая иллюстрация аватара: `app/assets/images/profile/avatar.jpg`. Если файла нет, видна первая буква имени. Это общий файл оформления, личные аватары через загрузку пока не реализованы.

Фото материалов добавляются через формы профиля; они сохраняются в `public/uploads/profile_submission/image/<id>/`, записи — в PostgreSQL. Существующие фотографии карточек маршрутов берутся из `app/assets/images/routes/`.

## Запуск

После получения кода выполнить `bin/rails db:migrate`. Регистрация создаёт пользователя через интерфейс — учётные данные в seeds не добавляются.

Нужен запущенный Rails и PostgreSQL: GitHub Pages не исполняет регистрацию и работу с базой.
